# tools

## watch-readings.py

pulse 를 읽는 페이지. 프로토타입 저장소에서 가져왔습니다 — 거기서는 이것이 판독을
읽는 유일한 수단이었습니다.

```bash
tools/watch-readings.py
# 그리고 http://localhost:8770
```

세 탭이고, 출처가 둘입니다.

```
판독   artel-pulse.jsonl 을 1초마다 다시 읽는다        파일
원문   같은 것을, 접지 않고 그대로                      파일
성능   SDK 의 로컬 소켓에 직접 붙는다                   ws://127.0.0.1:17311/ws
```

**원문** 탭은 채널이 보낸 문서를 그대로 냅니다 (최근 50건). 판독 탭이 접어서 그린 것과
나란히 대면 접는 과정에서 잃은 것이 보입니다. 성능 보고는 여기 없습니다 — 파일이 아니라
소켓이 나르는 다른 채널입니다.

**판독 시작 / 판독 종료** 버튼이 성능 탭과 같은 소켓으로 `start_readings` ·
`stop_readings` 액션을 보냅니다. 판독은 연결이 아니라 **세션**입니다 — 연결은 도구가 봐도
된다는 말이고, 시작은 런이 begun 했다는 말입니다. 둘을 갈라 둔 이유는 전체 씬 순회도
연결에서 시작하는데 그 순회 중의 판독이 아무도 걸어간 적 없는 화면을 현재 상태라고 말하기
때문입니다.

소켓이 없으면 두 버튼은 눌리지 않습니다.

**정지 화면에서는 아무것도 오지 않는 것이 맞는 동작입니다.** 게이트가 변한 것만 내보내므로
가만히 있는 화면은 전량 한 줄 뒤로 침묵합니다. 그래서 헤더가 판독이 도는지와 마지막 판독이
언제였는지를 적습니다 — 그것이 없으면 "안 켰다" 와 "켰는데 조용하다" 가 화면에서 같아
보입니다.

게임을 Play 로 다시 시작하면 세션도 새로 시작합니다. 연결로는 판독이 안 켜지므로 **매번
판독 시작을 눌러야 합니다.** 거절당하면 이유를 그대로 적습니다 — 출시 빌드는
판독을 하지 않고, 그 사실이 안 보이면 죽은 버튼이 살아 있는 것처럼 보입니다.

**판독** 탭은 일부러 멍청한 소비자입니다. 채널은 씬이 바뀔 때 전량을, 그 외에는 차이만
보내므로 읽는 쪽이 마지막 전량을 쥐고 그 위에 차이를 얹어야 합니다. 그 일을 여기서 하는
것이 요점입니다 — 페이지가 도착한 것만으로 화면의 현재 상태를 보일 수 있으면 채널이 충분한
것이고, 못 보이면 부족한 자리가 논쟁이 아니라 눈에 보입니다.

**성능** 탭이 파일이 아니라 소켓을 읽는 이유는 프레임 시간이 pulse 에 없고 앞으로도 없을
것이기 때문입니다. 그것은 게임이 아니라 게임을 돌리는 프로세스에 관한 값이고, 소켓이 이미
듣는 쪽에 나르고 있습니다. `ArtelTestPageManager` 가 켜져 있어야 열립니다.

SDK 자신의 테스트 페이지(`http://127.0.0.1:17310/`)는 `GAME_STATE` 를 그립니다. 다른
질문에 답하는 다른 채널이라 합치지 않고 따로 둡니다.

### 인자

```
--file    artel-pulse.jsonl 경로. 기본값은 WordVenture 의 persistentDataPath
--socket  SDK 로컬 소켓. 기본 ws://127.0.0.1:17311/ws
          경로 /ws 가 필요하다. 루트로는 포트가 열려 있어도 501 로 거절된다
--port    이 페이지를 낼 포트. 기본 8770
```
